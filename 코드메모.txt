[2] 단일 파일 설치기 (요세의수호자_설치.exe)
----------------------------------------------------
게임 전체가 exe 안에 들어 있어 인터넷 없이 설치된다.

  요세의수호자_설치.exe 더블클릭
    → %LOCALAPPDATA%\YoseGuardian\app 에 설치
    → 바탕화면·시작메뉴 바로가기 생성
    → 게임 실행

최신 판으로 설치:
  요세의수호자_설치.exe https://github.com/<아이디>/<저장소>/releases/latest/download/game.zip

다른 폴더에 설치:
  set YOSE_TARGET=D:\Games\Yose
  요세의수호자_설치.exe

다시 빌드:
  npm run single        → 요세의수호자_설치.exe (약 624KB, 게임 내장)
  npm run release:all   → 런처 zip + 단일 exe 한 번에


[3] 단일 exe 구조 (tools/single-launcher.cs)
----------------------------------------------------
  payload.zip  (launcher.ps1 + install.ps1 + game.zip)
        ↓ exe 안에 리소스로 내장
  실행 → %TEMP% 에 풀기 → launcher.ps1 실행 → 설치 → 게임 시작

핵심 코드 — 설치 위치 결정:

  string target = Environment.GetEnvironmentVariable("YOSE_TARGET");
  if (argv != null && argv.Length > 1 && !string.IsNullOrWhiteSpace(argv[1]))
      target = argv[1].Trim().Trim('"');
  if (string.IsNullOrWhiteSpace(target))
  {
      target = Path.Combine(
          Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData),
          "YoseGuardian", "app");
  }
  target = Path.GetFullPath(target);

핵심 코드 — 설치 성공 판정 (실행 스크립트는 필수가 아니다):

  bool hasGame = File.Exists(Path.Combine(target, "client", "dist", "index.html"))
                 && File.Exists(Path.Combine(target, "server", "index.js"));

핵심 코드 — 실행 스크립트가 없으면 서버를 직접 띄운다:

  var run = new ProcessStartInfo("cmd.exe",
      "/c start \"\" /min \"" + ResolveNode(target) + "\" \"" + server + "\" --prod");
  run.WorkingDirectory = target;


[4] 빌드 스크립트 (tools/build-single.mjs)
----------------------------------------------------
5단계:
  [1/5] game.zip 확인 (없으면 pack-release 로 생성)
  [2/5] payload 스테이징 (launcher.ps1 · install.ps1 · game.zip)
  [2-b] 무결성 검사 ← 중요
  [3/5] payload.zip 만들기
  [4/5] csc 로 컴파일 (리소스 내장)
  [5/5] 요세의수호자_설치.exe 복사

무결성 검사 코드 (설치가 깨지는 걸 빌드 단계에서 막는다):

  if (!installSrc.includes('--prod')) {
    console.error('  [실패] install.ps1 에 --prod 가 없습니다 — 설치 후 화면이 뜨지 않습니다');
    process.exit(1);
  }
  const gamePkg = readZipEntry(gameZip, 'package.json');
  try { JSON.parse(gamePkg); }
  catch (err) {
    console.error(`  [실패] game.zip 안의 package.json 이 깨졌습니다: ${err.message}`);
    process.exit(1);
  }

컴파일 명령 (csc):
  csc /target:exe /codepage:65001 /resource:<payload.zip>,payload.zip
      /reference:System.IO.Compression.dll
      /reference:System.IO.Compression.FileSystem.dll
      /out:<출력.exe> tools/single-launcher.cs

[10] 문제가 생기면
----------------------------------------------------
화면이 안 뜬다
  → node server/index.js --prod 로 실행했는지 확인
    (--prod 가 없으면 client/dist 를 서빙하지 않는다)

npm install 이 실패한다
  → package.json 이 깨졌는지 확인
    node -e "JSON.parse(require('fs').readFileSync('package.json','utf8'))"

빌드는 되는데 실행이 안 된다
  → client/dist/index.html 이 있는지 확인
  → node server/index.js --prod 로 직접 실행해 로그 확인

게임실행.cmd 가 안 된다
  → REPO 는 %~dp0 (이 파일이 있는 폴더) 기준이다
  → 다른 폴더로 옮겨도 그대로 동작한다

[14] 콘솔 창 없이 실행 (게임실행.vbs)
----------------------------------------------------
증상 : 게임실행.cmd 를 더블클릭하면 검은 창이 계속 떠 있었다.
원인 : 그 창이 서버(node server/index.js --prod)를 직접 돌리고 있었다.
해결 : 창 없이 켜는 런처를 따로 두고, cmd 는 그것만 부르고 바로 끝난다.

· 게임실행.vbs  — wscript 로 실행 → 콘솔 창이 없다
    · 이미 켜져 있으면 브라우저만 연다
    · node 위치를 Program Files / LOCALAPPDATA / PATH 순으로 찾는다
    · 서버가 응답할 때까지 기다렸다가 브라우저를 연다
· 게임실행.cmd  — 첫 실행이면 npm install/build 만 하고, vbs 를 부르고 종료
· 설치본도 같은 방식 : install.ps1 이 게임실행.vbs + 게임실행.cmd 를 만든다

· 끄는 법 : 게임 안의 [게임종료] (서버가 스스로 종료된다)
            또는 작업 관리자에서 node.exe 종료
· 확인 : wscript.exe //nologo 게임실행.vbs → 창 없이 서버 200 OK

[15] 멀티플레이 서버 주소 (마인크래프트 방식)
----------------------------------------------------
하고 싶었던 것 : 서버만 켜 두면, 다른 PC 에서 주소만 넣고 접속하기.

· 서버 쪽 (이미 되어 있던 것)
    · HOST 기본값 0.0.0.0  → 같은 공유기의 다른 PC 가 붙을 수 있다
    · PORT 기본값 3001
    · .env 의 CLIENT_ORIGIN 이 http://localhost:5173 이면 **다른 PC 가 막힌다**
      → CLIENT_ORIGIN=* 로 바꿨다(출처를 그대로 되돌려주므로 credentials 도 OK)

· 클라이언트
    · 메뉴 → 멀티플레이 → [서버 주소] 칸 + [접속]
        ip / ip:port / http://ip:port 모두 허용, 포트를 빼면 3001
        비우고 접속하면 내 PC(지금 서버)로 복귀
    · net.js  normalizeServerAddress()  주소 정리
    · net.js  setApiBase() / api()      로그인·저장·순위표도 그 서버로
    · Net.setServer(url)               소켓 대상 교체
    · main.js connectServer(address)    위 셋을 묶은 처리

· 쓰는 법
    1) 서버 PC : node server/index.js  (또는 게임 실행)
    2) 서버 PC 의 IP 확인 : ipconfig → IPv4 (예: 192.168.0.10)
    3) 다른 PC : 게임 실행 → 멀티플레이 → 서버 주소에 192.168.0.10:3001 → 접속
    4) 방을 만들거나 초대코드로 참가 (기존 방식 그대로)

· 확인 : 3002 포트에 서버를 띄우고 다른 출처에서
        REST(health/login) + socket.io + 방 생성까지 전부 성공

[18] 긴급 수정 — 게임이 시작되지 않던 문제 (v1.0.10)

  증상 : 게임 실행 → 메뉴조차 안 뜨고 화면이 멈춤 (시작 불가)
  원인 : main.js `_adminHint()` 가 safe() 를 쓰는데 main.js 에 정의가 없었다
         → ReferenceError: safe is not defined → [boot] 치명적 오류로 부팅 중단
         (v1.0.9 에서 관리자 안내를 되살릴 때 들어간 코드)
  수정 : main.js 상단에 안전 실행 헬퍼 정의
         const safe = (fn, fallback = undefined) => { try { return fn(); } catch { return fallback; } };
  검증 : npm run boot (tools/boot-check.mjs) — 실제 Chrome headless 로
         [부팅 → 싱글 플레이 → 혼자 지키기] 9개 검사 전부 통과

  · 왜 테스트가 못 잡았나 : ui-dom 은 DOM 스텁만 검사하고 main.js 를 실제로 부팅하지 않는다.
